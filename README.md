# Плагины и утилиты `script_s21_school`

Данный набор скриптов, алиасов и утилит предназначен для автоматизации рутинных задач при обучении в школе разработки (School 21 / Sber). Скрипты помогают ускорить работу с Git, настройкой отладки в VS Code, проверкой кода на утечки памяти и соответствием стилевым нормам.

## Установка
Скрипты автоматически интегрируются в вашу систему при запуске `init_setup.sh`. После установки все алиасы и функции становятся доступны в терминале сразу или после выполнения команды `restart`.

---

## Основные алиасы и навигация (`alias.sh`)
Эти команды добавляются в ваш `.bashrc` для быстрого доступа к функциям:

* **`restart`** — Перезагружает конфигурацию оболочки (`source ~/.bashrc`). Полезна после установки новых плагинов или изменения `.bashrc`.
* **`work`** — Мгновенно переносит вас в корневую директорию текущего Git-репозитория.
* **`gsd`** — Быстрое переключение на ветку `develop` (`git switch develop`).
* **`gsn`** — Быстрое переключение на ветку с вашим именем пользователя (`git switch $(whoami)`).
* **`info`** — Показывает версии установленных утилит для проверки кода (`clang-format`, `cppcheck`, `valgrind`).
* **`init`** — Копирует стандартный `Makefile` из папки плагинов в директорию `src/` текущего проекта (если она существует).
* **`s21_lint`** и **`keepalive`** — Прямой вызов скомпилированных утилит (см. раздел *Дополнительные бинарные утилиты*).

---

## Работа с Git (`git.sh`)
Утилиты для быстрого клонирования и ревью кода.

* **`gclone <ссылка_на_репозиторий>`**  
  Клонирует репозиторий, переходит в него, автоматически создает и переключается на ветку `develop`, а затем открывает проект в VS Code (`code .`).
* **`staff <ссылка_на_репозиторий>`**  
  Инструмент для **Peer Review**. Клонирует репозиторий (ветку `develop`) в специальную папку `~/Desktop/staff`, добавляет к названию папки текущую дату и время (чтобы не перезаписывать старые проверки), и открывает проект в VS Code.
* **`getkey`**  
  Генерирует SSH-ключ (алгоритм ED25519) без парольной фразы и сразу выводит публичный ключ в терминал для удобного копирования.

---

## Отладка и VS Code (`VS_debug.sh`)
* **`vdb`** (VS Debug)  
  Автоматически настраивает файлы `launch.json` и `tasks.json` в папке `.vscode` для отладки C/C++ проектов в Visual Studio Code.
  * `vdb` — Интерактивный режим. Спросит, нужно ли перезаписать существующую папку `.vscode`, и попросит ввести имя исполняемого файла (по умолчанию `a.out`).
  * `vdb -f` или `vdb --force` — Принудительный режим. Без вопросов удаляет старую папку `.vscode` и создает новую с настройками для файла `a.out`.

## Проверка стиля и статический анализ

### Автоматическое форматирование (`format_style.sh`)
* **`fixformat`**  
  Находит все `.c` и `.h` файлы в текущей директории и применяет к ним стандарт **Google** через `clang-format`. Сначала показывает, какие ошибки есть, затем автоматически исправляет их, и в конце проводит финальную проверку.

### Статический анализ (`cppcheck.sh`)
* **`cpp_check`**  
  Запускает `cppcheck` для всех `.c` и `.h` файлов в текущей директории. Включает все проверки (`--enable=all`), но подавляет предупреждения о недостающих системных заголовках.

## Сборка и тестирование проектов (`Makefile`)
В папку `src/` (через команду `init`) копируется универсальный `Makefile` для сборки учебных проектов (Pong, Pong Interactive, Game of Life).

**Основные команды:**
* `make` — Запускает интерактивное меню выбора проекта для сборки.
* `make pong` / `make pong_int` / `make gol` — Сборка и запуск конкретного проекта.
* `make format` — Проверка кода на соответствие стилевому стандарту (через `clang-format`).
* `make cpp` — Запуск статического анализатора `cppcheck`.
* `make mem` — Проверка на утечки памяти. В Linux используется `valgrind`, в macOS — `leaks`. Также поддерживается запуск с `AddressSanitizer`.
* `make clean` — Удаляет все скомпилированные объекты, исполняемые файлы и артефакты сборки.
* `make clear` — Очищает исходный код от всех комментариев (полезно для подготовки к сдаче проекта).
* `make help` — Выводит справку по всем доступным целям Makefile.

## Дополнительные бинарные утилиты
В папке `plugins` также находятся скомпилированные ELF-бинарники, которые расширяют функционал:

* **`s21_lint`** — Кастомная утилита для комплексной проверки проекта на соответствие внутренним стандартам. 
* **`keepalive`** — Утилита для поддержания сессии или процесса в активном состоянии (предотвращает таймауты и отключения).
